# Помощник заполнения журнала

Локальное веб-приложение для поиска преподавателя в расписаниях DOCX и подсчёта часов по предметам.

## Локальный запуск

Требуется Node.js 24 LTS или более новая LTS-версия.

```powershell
npm ci
npm start
```

Приложение откроется по адресу <http://127.0.0.1:5177/>. Сервер по умолчанию принимает подключения только с этого компьютера.

DOCX-файлы расписаний хранятся в `schedules/` и включаются в Git. Папка `Старое/` с архивными расписаниями исключена.

## Запуск на VDS в Docker

Нужны Docker Engine с Compose V2, доменное имя, направленное на IP-адрес VDS, и открытые входящие порты 80 и 443.

1. Клонируйте репозиторий на сервер и перейдите в его папку.
2. Убедитесь, что актуальные DOCX-файлы есть в `schedules/`. Они попадут на сервер вместе с клоном репозитория. Каталог должен быть доступен контейнеру на чтение и выполнение, файлы — на чтение.
3. Создайте `.env` из шаблона и задайте домен и учётные данные:

   ```sh
   cp .env.example .env
   ```

   Установите `DOMAIN`, `AUTH_USER` и `AUTH_PASSWORD`. Для пароля можно сгенерировать безопасное hex-значение командой `openssl rand -hex 32`.

4. Запустите приложение с Caddy:

   ```sh
   docker compose --profile production up -d --build
   ```

Caddy принимает внешний трафик на 80/443, получает TLS-сертификат и проксирует запросы к приложению. Приложение дополнительно защищено HTTP Basic Auth. Порт приложения на хосте привязан к `127.0.0.1`; расписания доступны контейнеру только для чтения и не попадают в Docker-образ.

Проверить состояние и журналы:

```sh
docker compose ps
docker compose logs -f app caddy
```

Обновить приложение после `git pull`:

```sh
docker compose --profile production up -d --build
```

Папка `schedules/` и именованный том Caddy сохраняются при обновлении контейнеров. Для остановки:

```sh
docker compose --profile production down
```

Если на VDS уже настроен HTTPS reverse proxy на хосте, запустите только `app` командой `docker compose up -d --build`; проксируйте трафик на `127.0.0.1:5177`. Не публикуйте порт приложения напрямую в интернет.

## GitHub

Текущие расписания из `schedules/` входят в Git, поэтому они появятся на VDS после клонирования. `.env`, архив `Старое/`, `node_modules/` и локальные результаты исключены. Не добавляйте `.env` и секреты в репозиторий.

Если локальный Git-репозиторий ещё не создан:

```sh
git init -b main
git add .
git status --short
```

Проверьте, что в списке нет DOCX и `.env`, затем создайте пустой репозиторий на GitHub, добавьте его как `origin`, сделайте первый commit и отправьте ветку `main`.

GitHub Actions запускает `npm ci`, `npm test` и сборку Docker-образа при push и pull request. Сборка образа не публикует его в реестр.
